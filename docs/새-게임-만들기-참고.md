# 교육용 웹 게임 만들기 참고 문서

「가래떡 마을의 황금 들판」(2026 농업인의 날)을 만들고 실제 수업에서 운영하면서 얻은 원칙입니다.
새 게임을 시작할 때 새 대화창에 이 문서를 그대로 붙여 넣고 시작하면 됩니다.

---

## 1. 꼭 지킬 원칙 (실제로 좋았던 점)

### ① 서버가 죽어도 게임은 끝까지 (오프라인 모드)
- 게임 진행은 모두 **태블릿 안에서** 처리하고 저장(LocalStorage). 서버는 점수판·순위만 담당.
- 서버로 보낼 기록은 **대기열에 쌓아 두었다가** 서버가 살아나면 전송.
- 서버 오류가 나도 화면에 에러를 띄우지 말고 "오프라인" 표시만. 학생은 모르고 계속 플레이.
- 실제로 2026-11-11 서버가 15시간 꺼졌지만 수업은 문제없이 진행됨.

### ② 활동지와 짝을 이루는 게임
- 게임 속 대사에 **활동지 정답이 그대로** 나오게 설계 → 버튼만 누르지 않고 읽게 됨.
- 활동지 내용은 파일 하나(`content`)에 쓰고, 그 파일에서 **학생용·교사용 PDF와 Word** 를 자동으로 만듦.
- 교사용엔 정답(빨간 글씨), 수업 흐름(도입-게임-정리), 지도 팁, 교과 연계표.
- 활동지 구석에 **게임 QR 코드** (주소는 바뀌지 않으므로 인쇄해도 안전).

### ③ 무료 DB 에 부담 주지 않기
- 순위·전광판은 **자주 묻지 않기**: 45초 이상 간격, 화면이 안 보이면 멈춤, 실패하면 간격을 늘림.
- 실패한 요청 재시도는 **점점 길게**(8초 → 16초 → 32초 … 최대 5분) + 태블릿마다 무작위로 흩기.
- 여러 명이 같이 보는 결과(순위 TOP)는 DB 에 **몇 초 캐시**해서 함께 쓰기.
- **읽기만 하는 요청은 DB 에 쓰지 않기** (요청 횟수 기록도 쓰기임).
- **DB 함수 안에서 외부 API 를 기다리지 않기.** 기다려야 한다면 그동안 어떤 행도 잠그지 않기.
  (이번 장애의 직접 원인: 학교 검색이 NEIS 를 기다리는 동안 학교 IP 행을 잠가 같은 학교 요청이 줄줄이 막힘)
- Supabase 는 브라우저 요청(anon)을 **3초 넘으면 강제 취소** → 모든 함수는 1초 안에 끝나게.
- 학교는 **학생 전체가 공인 IP 하나**를 같이 씀 → IP 기준 제한은 넉넉하게, 진짜 방어는 세션 기준.

### ④ 배운 내용을 다시 점검하는 장치
- **📒 배움 노트**: 끝낸 미션의 핵심 내용만 모아 언제든 다시 보기 (안 한 미션은 잠김).
- **다시 듣기**: 미션을 끝낸 뒤 해당 NPC·장소에 다시 가면 배운 내용을 다시 들려줌.
- **정답 단어 강조**: 대사 속 핵심 단어를 노란 형광펜으로 (`**단어**` 표시 한 가지 방법으로 통일).
- **확인 퀴즈**: 미션 끝에 OX 1문제, 틀리면 해설 보고 다시 풀어야 보상. 마지막엔 보너스 퀴즈(선택, 추가 점수).
- 배움 내용은 **한 곳(데이터 파일 하나)** 에 정의하고 노트·다시 듣기·퀴즈·활동지가 모두 그걸 씀 → 내용이 서로 어긋나지 않음.

### ⑤ 초등학생용 화면: 귀엽고 단순하게
- 둥근 모서리, 따뜻한 색, 큰 글씨·큰 버튼 (태블릿 손가락 기준 최소 48px).
- 한 화면에 할 일은 하나. 다음 목적지는 **발밑 화살표**와 머리 위 **❗** 로 안내.
- 이야기 속 인물(촌장님 등)이 **튜토리얼을 이야기로** 안내 (걷기 → 둘러보기 → 말 걸기 → 줍기 → 미션).
- 미션은 **순서대로** 열리고, 끝날 때마다 다음 NPC 로 이야기가 이어짐.
- 효과음과 배경음악(코드로 만든 소리라 파일 불필요), 소리 켜기/끄기 버튼.
- 대사는 짧게, 한 줄에 한 생각. 3~4학년도 읽을 수 있는 말로.

### ⑥ 입력은 최소, 로그인은 없이
- **학교 검색 + 닉네임**만. 이름·번호·비밀번호·이메일 받지 않음.
- 닉네임은 비속어 필터(우회 표현 포함), 학교 이름은 공식 이름으로 고정(위조 방지).
- 기기 안에 임시 ID 를 만들어 새로고침해도 이어하기.

## 2. 태블릿·교실 환경에서 배운 것

- 학생 기기는 대부분 **갤럭시 탭(안드로이드)·크롬북**, 가끔 **오래된 브라우저** → 최신 기능은 대체 코드 준비
  (예: `crypto.randomUUID` 없음, `AbortSignal.timeout` 없음). 빌드 대상을 크롬 87·사파리 14 수준으로.
- 화면 키보드가 입력칸을 가림 → 키보드 위로 스크롤, 목록은 바깥을 눌러도 사라지지 않게.
- 가로/세로 화면 모두 점검 (세로 태블릿에서 버튼 글자가 세로로 꺾이는 문제 등).
- 입장은 **교실 화면에 QR 을 크게 띄우고** 태블릿으로 찍기 → 게임 안에 QR 버튼 (`?qr`).
- 터치: 왼쪽 조이스틱 + 오른쪽 큰 버튼, 손가락 두 개가 서로 방해하지 않게.
- 저사양 기기용 그래픽 품질 자동 낮춤, 전체 화면 버튼.
- **"처음부터" 버튼**: 진행만 초기화하고 점수·기록은 유지 (다시 깨도 점수 중복 없음).
- 다 끝낸 학생용: 내 기록 다시 보기, 숨은 보너스(개구리처럼), 보너스 퀴즈.

## 3. 기술 구성 (그대로 다시 써도 좋음)

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | Vite + React + three.js(@react-three/fiber) + zustand | 귀여운 로우폴리 3D, 빠른 개발 |
| 배포 | GitHub Pages + GitHub Actions | 무료, 기본 브랜치에 푸시하면 자동 배포 |
| 서버 | Supabase(무료) — 테이블 + SQL 함수만 | 서버 프로그램 없이 함수(RPC)로 점수·순위 |
| 보안 | 테이블 직접 접근 차단(RLS), 공개 함수만 허용, 점수는 서버가 계산·중복 방지 | 브라우저에서 점수 조작 불가 |
| 무중단 배포 | 직전 배포 파일을 14일간 같이 올림 + 로드 실패 시 1회 자동 새로고침 | 수업 중 배포해도 안 끊김 |
| 테스트 | 로컬 Postgres 로 SQL 테스트, Playwright 로 태블릿 화면 자동 플레이 | 배포 전에 확인 |

- SQL 파일은 **여러 번 실행해도 안전하게** 작성 (Supabase SQL Editor 에 통째로 붙여 실행).
- 공개 키(publishable key)는 GitHub 저장소 **Variables** 에, 서비스 키는 절대 화면 코드에 넣지 않기.

## 4. 개발 순서 (추천)

1. 기획: 학습 목표 → 미션 5~6개 → 각 미션에서 배울 핵심 문장(= 활동지 정답) 먼저 정하기
2. 오프라인으로 끝까지 플레이되는 게임 (서버 없이)
3. 이야기·튜토리얼·순서대로 열리는 미션, 효과음·음악
4. 배움 노트·다시 듣기·확인 퀴즈 (배움 내용 데이터 하나로)
5. 서버(점수판·순위) 붙이기 — 위 ③ 원칙대로
6. 태블릿·세로 화면·오래된 브라우저 점검, QR 입장
7. 활동지(학생용·교사용 PDF/Word), 홍보 글과 화면 캡처
8. 행사 전: 동시 접속 테스트, 행사 당일만 서버 사양 올릴지 결정, 장애 점검 문서 준비

## 5. 운영할 때

- 장애가 나면: Supabase **Logs**(오류 메시지) → **Reports**(CPU·메모리·연결 수) 순서로 보기.
- 무료 플랜 로그는 **약 1일만** 남음 → 문제가 생긴 날 바로 확인·내려받기.
- 자세한 점검 방법: 이 저장소의 `docs/운영-장애-점검.md`
